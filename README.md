# YOKABIO サイト 編集ガイド

> **▶ [公開サイト（Home）を開く](https://yokabio2026.github.io/biomod_website/)**
> **▶ [練習用ページ（sandbox）を開く](https://yokabio2026.github.io/biomod_website/sandbox.html)**
> （練習用ページは、サイトのメニューには出ません。ここからだけ開けます）

チームメンバー向けの、サイトの編集方法です。HTMLが詳しくなくても大丈夫です。
**「文章だけを書き換える」** なら、この表のとおりにやればOKです。

---

## 1. まず覚える3つのルール

1. **`main`（公開中のサイトの本体）に直接書かない。** 変更は必ず「変更の提案（Pull Request）」で出し、**HTMLチェックが緑なら自分で Merge して公開し、公開後に見た目を確認**します（手順は 5 を見てください）。管理者の許可は要りません。
2. **触らない場所には、基本的に触らない。** メニュー・`<script>`・`<link>` は、全ページに影響します（3 の表）。変えるときは、チャットで一言知らせてください。デザイン（`style.css`）は、8 の手順で進めます。
3. **迷ったら `sandbox.html` で試す。** 何を壊しても本番には影響しません（7）。

## 2. ファイルの見方

| ファイル | 内容 |
|---|---|
| `index.html` | Home |
| `project.html` | Project（background / The problem / Challenges / Solutions / Our goals and achievements） |
| `design.html` `simulation.html` `experiment.html` `future.html` `elsi.html` `team.html` | それぞれのページ（今は仮の文章） |
| `sandbox.html` / `sandbox.css` | **練習用のページとCSS**（メニューにも検索にも出ません。ここに書いたデザインは本番に影響しません） |
| `images/` | サイトで使う画像を入れるフォルダ（[ルール](images/README.md)） |
| `videos/` | サイトに直接置く短い動画（mp4）を入れるフォルダ（[ルール](videos/README.md)） |
| `style.css` | 色・大きさ・余白などの見た目（変えたいときは 8 の手順で） |
| `script.js` | 検索・マウスの動きなどの機能（全ページに影響するので、変えるときはチャットで一言） |
| `tools/check_html.py` | HTMLの崩れを調べるチェック（自動で動きます） |

## 3. どこを触ってよいか

各ページの中身は、次のように並んでいます。

```html
<header class="navbar"> … </header>     ← ❌ 触らない（メニュー）

<main class="content">                  ← ✅ この中だけ編集する
    <div class="page-hero-header …">     ← 上の大きな帯（見出し）
        <h1>Design</h1>                   ← ✅ 帯の中の文字は変えてOK
    </div>

    ここに文章・セクションを書く
</main>

<footer class="site-footer"> … </footer> ← ❌ 触らない（フッター）
<script src="script.js"></script>        ← ❌ 触らない
```

**ルールは「`<main>` から `</main>` の間だけ」です。**

## 4. コピーして使えるひな形

下のブロックをコピーして、`<main>` の中の好きな位置に貼り付け、文字だけ書き換えてください。
**書き換えるのは日本語（または英語）の文字の部分だけ**です。`<` と `>` で囲まれた部分（タグ）や、`class="…"` はそのままにしてください。

### ① 見出し付きのセクション（いちばんよく使う）

```html
<div class="content-section">
    <h2 class="section-title">見出し</h2>
    <div class="content-space">
        <div class="section-text">
            <p>
                1行目の文章<br>
                2行目の文章
            </p>
            <p>
                次の段落の文章
            </p>
        </div>
    </div>
</div>
```

- 文章の途中で改行したいところには `<br>` を入れます。
- 新しい段落にしたいときは、`<p> … </p>` を1つ増やします。
- **`<p>` で始めたら、必ず `</p>` で閉じてください。**（閉じ忘れが、崩れの原因のいちばんです）

### ② リンク

```html
<a href="https://example.com">表示したい文字</a>
```

### ③ 太字

```html
<strong>強調したい文字</strong>
```

### ④ YouTube動画を埋め込む（Home の「Youtube Video」など）

動画のURLが `https://www.youtube.com/watch?v=ABCDEFG` なら、`ABCDEFG` の部分が動画IDです。

```html
<iframe width="560" height="315"
        src="https://www.youtube.com/embed/ABCDEFG"
        title="YouTube video" allowfullscreen></iframe>
```

### ⑤ 画像を貼る

**手順は2段階です**（先に画像をアップロードして、次に文章側で呼び出します）。

1. **画像をアップロードする**
   - [images フォルダ](images/) の画像ルール（ファイル名は半角英数字、横幅1600px以内、500KB以下）を守って用意します。
   - GitHub で `images` フォルダを開き、**Add file → Upload files** に画像をドラッグします。
   - **Commit changes…** →「Create a new branch for this commit and start a pull request」を選び、**Propose changes** →**Create pull request**。
2. **同じ Pull Request の中で、ページに貼る**
   - 画面左上のブランチ名（`main`）を押して、**さきほど作ったブランチ**に切り替えます。
   - 貼りたいページを開いて編集（鉛筆アイコン）し、貼りたい場所（`<div class="section-text">` の中）に次を書きます。

```html
<img src="images/ファイル名.jpg" alt="画像の説明">
```

   - 保存（Commit changes…）は、**そのブランチへ**行います（「Commit directly to the …ブランチ」を選択）。
   - ファイル名が違うと、HTMLチェックが赤くなって教えてくれます（大文字・小文字も区別されます）。

### ⑥ 動画を貼る（短い動画を、サイトに直接置く場合）

長い動画・音が大事な動画・大きい動画は、④ の **YouTube** を使ってください。
**短い動画（数十秒まで、25MB以内）** は、mp4 のファイルをそのままサイトに置けます。

手順は画像（⑤）と同じで、**2段階**です。

1. **動画をアップロードする**
   - [videos フォルダ](videos/) のルール（ファイル名は半角英数字、25MB以内）を守って用意します。
   - GitHub で `videos` フォルダを開き、**Add file → Upload files** に動画をドラッグします。
   - そのあとの保存と、ブランチの切り替えは ⑤ と同じです。
2. **ページに貼る**（`<div class="section-text">` の中に書きます）

GIFのように、**音なしで自動で繰り返す**場合：

```html
<video src="videos/ファイル名.mp4" autoplay loop muted playsinline></video>
```

再生ボタンなどを出して、**普通の動画として見せる**場合：

```html
<video src="videos/ファイル名.mp4" controls></video>
```

- ファイル名が違うと、HTMLチェックが赤くなって教えてくれます（大文字・小文字も区別されます）。
- 画面の幅に合わせて、はみ出さずに縮んで表示されます。

### ⑦ 画像・動画を横に並べる

`<div class="media-row">` で囲むと、中に入れた画像・動画が、**横に等分で並びます**（2つでも、3つでも使えます）。

```html
<div class="media-row">
    <img src="images/ファイル名1.jpg" alt="画像1の説明">
    <img src="images/ファイル名2.jpg" alt="画像2の説明">
</div>
```

- 3つ並べるときは、`<img …>` の行を1つ足します。
- 動画も同じです。`<img …>` の代わりに `<video src="videos/ファイル名.mp4" controls></video>` を入れます。
- 大きさ（縦横の比率）が近い画像を選ぶと、きれいに揃います。
- 見本は、練習用ページ `sandbox.html` の「layout samples」にあります（コピーして使えます）。

### ⑧ 文章の横に、画像・動画を置く

`<div class="media-text">` で囲み、**画像（または動画）を先、文章を後**に書きます。画像が**左**、文章が**右**になります。

```html
<div class="media-text">
    <img src="images/ファイル名.jpg" alt="画像の説明">
    <div>
        <p>
            ここに、画像の横に置きたい文章を書きます。
        </p>
    </div>
</div>
```

**画像を右、文章を左**にしたいときは、書く順番はそのままで、`class` に **`media-text--reverse`** を足します。

```html
<div class="media-text media-text--reverse">
    <img src="images/ファイル名.jpg" alt="画像の説明">
    <div>
        <p>
            画像が右、文章が左になります。
        </p>
    </div>
</div>
```

- 文章の部分には、`<p> … </p>` を複数書いても大丈夫です。`<div>` と `</div>` で囲むのを忘れないでください。
- **画面が狭いとき（スマホなど）は、自動で縦に積まれます**（画像の下に文章が来ます）。

### ⑨ 画像を広く表示する（グラフ向け）

ふつうの画像は、文章と同じ幅までしか大きくなりません。グラフのように**小さい文字が入った画像**は、縮むと読みにくくなります。そのときは、`<img>` に **`class="media-wide"`** を足すと、文章より広く（最大1280px）表示されます。

```html
<img class="media-wide" src="images/ファイル名.png" alt="グラフの説明">
```

- 縦横の比率はそのままで、全体が同じ割合で大きくなります（引き伸ばしではありません）。
- 小さい画像を広げるとぼやけます。グラフは、**横幅1600px前後**で作った画像がおすすめです。
- スマホなど画面が狭いときは、画面の幅に収まります。
- 写真には付けなくて大丈夫です。

### ⑩ 画像に説明（出典など）をつける

`<figure>` で囲み、画像の下に `<figcaption>` で説明を書きます。灰色の小さい文字で、中央に表示されます。

```html
<figure>
    <img src="images/ファイル名.png" alt="グラフの説明">
    <figcaption>Fig. 1 図の説明や、出典をここに書きます。</figcaption>
</figure>
```

広く表示して、説明もつけたいときは、`<figure>` に `class="media-wide"` を足します（`<img>` には付けません）。

```html
<figure class="media-wide">
    <img src="images/ファイル名.png" alt="グラフの説明">
    <figcaption>Fig. 2 図の説明や、出典をここに書きます。</figcaption>
</figure>
```

見本は、練習用ページ `sandbox.html` の「layout samples」⑤〜⑦にあります。

### ⑪ 仮の文章を本物に置き換える

`design.html` などにある、次のような仮の1行は、消して ① のひな形に置き換えてください。

```html
<p>Design content will be added here.</p>
```

## 5. 編集のしかた（ブラウザだけでできます）

1. GitHub でこのリポジトリを開き、編集したいファイル（例：`project.html`）をクリックします。
2. 右上の **鉛筆アイコン（Edit）** を押します。
3. `<main>` の中の文章を書き換えます。（`Ctrl + F` で探すと早いです）
4. 右上の **Commit changes…** を押します。
5. **「Create a new branch for this commit and start a pull request」** を選び、**Propose changes** を押します。
   （ここで「main に直接」を選ぶと公開中のサイトが直接変わってしまうので、選ばないでください）
6. 次の画面で **Create pull request** を押します。
7. 数十秒〜数分待つと、**HTMLチェック**の結果が表示されます。
   緑のチェック ✅ なら問題なし。赤い ❌ なら、内容をクリックすると直す場所が出ます。
8. **HTMLチェックが緑なら、自分で公開します。**
   Pull Request の画面で **Merge pull request** → **Confirm merge** を押すと、公開サイトに反映されます（1〜2分かかります）。
   そのあと、**Delete branch** のボタンが出たら押して、作業用ブランチを片付けます。
   チェックが赤いときは、**Merge せずに**直してください。
9. **1〜2分後に、公開サイトを開いて、変えたページを必ず確認します。**
   崩れていたら、**すぐに Revert**（6 を見てください）で元に戻してください。

> 公開サイトは、GitHub のこのリポジトリのページの右側にある **Deployments → github-pages** から開けます。
> **今は、公開前の見た目を確認する「確認用URL」はありません**（Cloudflare をつなぐと使えるようになります）。
> 不安な変更は、先に `sandbox.html` で試してから、本物のページに反映してください（7 を見てください）。
> 同じ Pull Request の中で、直したいところを続けて編集してもかまいません（作業用ブランチを選んで、同じ手順で編集）。
> チームに共有したいときは、チャットで「〇〇ページを更新しました」と一言送ると親切です。

## 6. 失敗したとき・崩れたとき

**落ち着いてください。** すべての変更は履歴に残っているので、**自分で元に戻せます**。困ったら、チャットで相談してください。

- **公開したあとで崩れに気づいた**
  → 該当の Pull Request を開き、いちばん下の **Revert** ボタンを押す → 出てきた Pull Request を、自分で Merge する、で元に戻ります。
- **Merge する前（HTMLチェックが赤いとき）**
  → Merge せずに、ファイルを直して続けて保存すれば OK。やり直したいときは、その Pull Request を **Close** してください。
- **どこが悪いか分からない**
  → HTMLチェックの赤い ❌ を開くと、「○行目の `<p>` が閉じられていません」のように場所が出ます。
- **節目のバックアップ**
  → 提出前などに、管理者が「タグ」を付けます（例：`backup-2026-11-01`）。その時点の状態をいつでも呼び出せます。（これは管理者の作業です）

## 7. 練習用ページ `sandbox.html`

- 自由に書き換えて試せるページです。メニューにも検索にも出ません（検索エンジンにも載らないよう設定済み）。
- **デザインを試したいときは `sandbox.css` に書きます。** `sandbox.html`（とそのコピー）にだけ反映され、本物のページには影響しません。
- 自分用に試すときは、`sandbox.html` をコピーして **`sandbox-自分の名前.html`** を作ると、ほかの人の練習と混ざりません。
- 練習用ページはHTMLチェックで間違いがあっても「警告」になるだけで、公開の邪魔になりません。
- ただし、URLを知っている人（＝チームメンバー）には見えます。**個人情報などは書かないでください。**
- 本番に反映したい内容ができたら、そのページから必要な部分だけをコピーして、本物のページに貼ってください。

## 8. デザインを変えたいとき

色・大きさ・余白などは `style.css` で決まっています。9人が同時に触ると、見た目がバラバラになったり、編集がぶつかったりするので、次の順番で進めます。

1. **まず試す**：`sandbox.css` に、変えたいルールを書いて Merge します（書き方の例がファイルの中にあります）。公開サイトの `sandbox.html`（URLの最後を `sandbox.html` にして開く）で、見た目を確かめられます。`sandbox.html` はメニューにも検索にも出ないので、本物のページには影響しません。
2. **チームで決める**：「こう変えたい」と、スクリーンショットなどでチャットに共有し、よければ進めます。
3. **本物に反映する**：`style.css` の該当部分を書き換える Pull Request を出します。
   - **1つの Pull Request では、1つの目的だけ**にします（例：「見出しの色を変える」）。
   - `style.css` を直す前に、チャットで「今から style.css を触ります」と一言伝えます。
     同時に同じ場所を直すと「Conflict（衝突）」と表示され、片方が出せなくなります。そのときは、チャットで相談してください。
4. HTMLチェックが緑なら、自分で **Merge** します。
5. **すぐに確認する**：1〜2分後に公開サイトで、**すべてのページ**（Home / Project / Design / Experiment / Future / ELSI / Team）を見ます。ブラウザの幅を狭くした表示（スマホ相当）も見てください。
   崩れていたら、**すぐに Revert** で戻し、チャットで共有してください（`style.css` は全ページに影響するため、事前に `sandbox.css` で十分に試してから反映するのが安全です）。

### 色を変えるときの注意
- 「メインの紫」`#2b1055` は、`style.css` の**5か所**に書かれています（上のメニュー・上の帯・フッター・検索結果の小さなラベル・見出しの文字）。
  `Ctrl + F` で `#2b1055` を探し、**全部**同じ色に変えてください。1か所だけ変えると、色がちぐはぐになります。
- マウスの動き（DNAの螺旋と光の粒）の色は `script.js` の中に書かれています。変えたいときは、チャットで相談してから進めてください。
- 色を変えたあとで、**文字が読みにくくなっていないか**（背景と文字の色の差）も確認してください。

## 9. 管理者向けメモ

- 新しいページを増やすとき：
  1. 既存ページをコピーして新しい `.html` を作る
  2. **全ページ**のメニュー（`<ul class="nav-links">`）に項目を足す（HTMLチェックが「メニューが違う」と教えてくれます）
  3. `script.js` の `PAGES` に新しいファイル名を足す（サイト内検索の対象になります）
- `style.css` の変更は、全ページの見た目が変わります。Merge の後に、公開サイトで全ページ・スマホ幅を見てください（8 の手順）。
- `script.js`（検索・マウス演出）の変更は、全員に影響します。変える人は、チャットで一言知らせる運用にしてください。
- 初期設定（GitHub・公開先・ログイン制限）は [docs/admin-setup.md](docs/admin-setup.md) を見てください。
- パソコンでチェックを実行する場合：`python3 tools/check_html.py`
